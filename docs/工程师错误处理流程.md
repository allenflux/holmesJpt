# 工程师错误处理流程

目标：点击一次“发现高频错误”，系统自动选任务、定时间范围，把频繁出现的错误整理成可核查、可下载的处理卡片。工程师直接看错误、证据链与下一步。

流程：**失败任务 → 关联错误日志 → 提炼典型样本 → 工程师处理卡片**。

[查看流程图](diagrams/log-investigation-flow.html)

## 怎样使用

1. **一键发现。** 点击“发现高频错误”，无需填写任务数、开始时间或结束时间。服务器在点击时确定最近24小时，最多选择50个当前失败任务，并固化本批名单；授权范围优先使用 prod。文件演示按快照观察时间回放。调度统计按创建时间选任务，不能把它当作实际执行时间。
2. **定向找错。** 在授权范围内按任务标识查关联日志，识别明确失败事件与异常。先定名单再查日志，本轮不新增全 Namespace 日志全集采集。
3. **按频率排序。** 将同类错误归组，每组挑选 1–2 条代表日志，按不同 Task ID 去重计算影响任务数，并按影响任务数从多到少显示。同一任务可能出现多类候选错误，组数不能相加当作失败任务总数。
4. **交付处理。** 阅读卡片，点击证据核查，下载单卡后人工交付工程师。建议负责人是待分配的角色；系统未自动派工，也未发送消息。

## 一张卡片包含什么

| 字段 | 内容 |
|---|---|
| 错误现象 | 已观察到的错误，简短说明；只有失败事件但没有异常细节时直接写明“异常细节未知” |
| 组件 / 节点 | 已知组件、`node_type` 或异常类；缺失写“未提供” |
| 影响任务数 | 本批匹配该错误组的去重任务数量，保留任务明细入口 |
| 代表日志 | 1–2 条脱敏摘录，列出日志时间与 Pod；不是原始日志全集 |
| 证据按钮 | 打开该卡实际引用的日志证据，能回查时间与任务关联依据 |
| 建议负责人 | 例如模型运行时工程师、应用工程师或平台工程师；均标记“待分配”，没有具体人员时不虚构姓名 |
| 处理建议 | 最多 3 条可执行检查，说明要核实的配置、资源或执行记录，避免无证据地要求重试或改生产参数 |

**单卡下载**用于人工交接，包含上述字段、证据引用和必要的判断边界；下载不代表已派工或已修复。

## 哪些错误可以合在一起

按 **错误签名 + 节点类型 / 组件 + 异常类 + 规范化错误消息** 聚合。规范化去掉任务 ID、时间和无意义动态值，但保留影响判断的资源差异：同域名的不同文件路径、不同模型或不同接口不能只因类型相同而合并。需要隐藏地址时，为不同规范化完整地址保留不同稳定资源别名。

`INCOMPLETE` 表示证据或归属尚有缺口，不是工程师要处理的错误类别，不作为主卡片标题。

## 没有日志或没有明确错误怎么办

放入**待补证据**列表，保留任务数量和下一步：核对 Task → Prompt 映射、实际执行时间窗、日志来源与采集状态。Task 与 Prompt 映射缺失仍可能导致 0 命中；调整 UI 不能保证补出不存在或未匹配的日志。

零日志任务不能让 LLM 造出错误。已有日志但没有明确失败事件时，也不能把普通上下文硬归为异常。模型只解释已引用的脱敏证据，不修改任务归属和规则统计。

**代表日志是事实摘录；卡片解释与建议是待复核判断；最终执行归属与根因需要执行 / 重试记录验证。** 候选错误可以先交工程师复核，无需把整页质量标记当作交接内容。


## LLM 怎样参与

配置模型后，一键发现会自动请求模型分析；无日志时跳过。页面在按钮旁公布模型和发送目的地。已有批次仍可单独请求解释。模型先看到任务概览和证据目录，自主选择只读工具：

| 工具 | 用途 |
|---|---|
| `get_error_samples` | 获取本批代表性错误事件 |
| `read_task_timeline` | 按时间读取单任务已保留的代表事件，不能当作完整执行历史 |
| `read_evidence` | 展开指定证据的脱敏结构化异常细节 |
| `compare_tasks` | 对比2–4个本批任务的已有摘要与错误证据 |

模型可以在工具结果基础上继续查证，再给出简短解释和排查建议；页面可展开查看实际调用记录。所有工具只读本批已采集、已脱敏的代表证据，不扩大采集时间窗或访问其他任务。最多4轮模型、6次工具调用，达到预算后收束；模型发现必须引用实际读取过的证据。零日志仍进入待补证据。

工程师卡片与任务计数继续由规则生成；模型补充解释，不会改写计数、执行归属、真实负责人或处理状态。已有模型解释直接复用，新模式不自动重跑旧报告。

## 频率的统计范围

卡片中的频率是本次自动样本内的去重任务数，最多50个，不能当作全平台24小时的总故障率。系统显示实际选中数量、自动确定的查询窗口和选样是否完整；同一任务可出现多种错误，各组人数不能相加。无命中任务单列待补证据，不会被隐藏，也不会降低统计分母。

## 进度与界面

页面保留一个发现按钮、一条进度条和错误证据列表。加载失败任务时名单尚未固定，使用等待动画，不显示0/0或估算百分比。名单取得后，进度按已处理任务数计算；包含无命中、采集失败和跳过，不能当作成功取证数。任务处理完后模型仍在分析时，阶段改为模型分析中，继续等待结果。调查结束、缺少证据、处理停止分别显示对应状态。

中英切换使用页内按钮并保存偏好。模型与发送目的地保留一行提示，完整说明可展开；详细执行状态、质量和调用过程默认收起。
