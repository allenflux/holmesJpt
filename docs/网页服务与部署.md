# 网页服务与部署

`web` 同时提供日志调查页面和通用问答。日志批次沿用 task_id / prompt_id 关联、失败任务聚合和 FluxDrop 归档；通用问答在服务端配置 `LLM_API_KEY` 后启用。默认直接进入页面，API 无需登录；以后启用可选网页密码时，页面与 API 使用同站 HttpOnly 会话。模型密钥只在服务端配置。

网站名称为 **Holmes**，默认使用 English，可在页面切换到中文。界面采用 Bootstrap 5.3.8 现成组件，CSS 与 JavaScript 直接引用官方 `cdn.jsdelivr.net`，固定版本并使用 SRI 完整性校验；运行浏览器需要能访问该 CDN。Bootstrap 不打入 JAR，应用自己的 CSS 与 JavaScript 仍随 JAR 由同源服务提供，密钥只在服务端配置。浏览器的 `localStorage` 仅保存语言偏好，`sessionStorage` 仅保存当前批次 ID；密码和 API Key 不存入这两类浏览器存储。

先在本机调试，确认线上任务 API、日志来源和问答配置，再将同一个打包产物部署到远端。下文的远端步骤是部署说明，不代表已经部署到生产主机。

## 本地启动

需要 JDK 27、Maven 3.9+，从项目根目录运行。程序自动读取启动工作目录下的 `.env`，也支持 `--env-file /绝对路径/.env` 显式指定；已有文件直接编辑，保留现有密钥和其他配置，不要用示例覆盖它。显式指定的文件不存在或不可读时会报错。

默认不需要网页密码，`HOLMES_WEB_PASSWORD` 缺失或留空时不显示登录页。已有 `.env` 若配置过网页密码，将该项留空并重启即可直接进入。本地 HTTP 使用以下设置：

```dotenv
HOLMES_WEB_PASSWORD=
HOLMES_WEB_SECURE_COOKIE=false
```

先运行明确标记的演示模式：

```bash
mvn package
java -jar target/holmes-java-0.1.0.jar web --demo --port 8080
```

浏览器打开 [http://127.0.0.1:8080](http://127.0.0.1:8080)，直接使用页面。日志演示使用六个合成失败任务，问答使用脚本模型；不需要模型 Key，也不会把演示问答发送到真实模型。演示模式仅用于从项目目录运行的本地验证，容器生产配置不包含 `--demo`。

以后需要登录时，可运行 `openssl rand -hex 24` 生成 48 位随机密码，填写到已有 `.env` 的 `HOLMES_WEB_PASSWORD` 并重启。非空密码支持 12–256 个字符；启用后浏览器使用该密码登录，密码不存入 localStorage 或 sessionStorage。

调试真实来源时，在已有 `.env` 中编辑相关条目：

```dotenv
HOLMES_LOG_TASKS_FILE=
HOLMES_LOG_FILE=
HOLMES_SCHEDULER_URL=http://216.176.194.30:18080
HOLMES_SCHEDULER_TOKEN=
HOLMES_SCHEDULER_TIMEZONE=Asia/Hong_Kong
HOLMES_GRAFANA_URL=https://sch-grafana.aiaipool.com
HOLMES_GRAFANA_DATASOURCE_UID=victorialogs
HOLMES_GRAFANA_TOKEN=
HOLMES_LOG_NAMESPACES=prod
HOLMES_TOOLS_FILE=config/tools-web.json
```

`HOLMES_LOG_TASKS_FILE` 留空时，服务自动通过线上统计 GET API 读取失败任务，无需人工准备文件。设置非空路径或 `--tasks` 时优先使用该文件；`web --demo` 始终使用固定样本。线上 `status=-1` 表示读取时失败，uuid / task_id 用作日志关联；来源缺少 prompt、attempt 或重试状态时，报告保留候选证据与 `observed_signatures`，主簇为 `INCOMPLETE`，不伪造最终执行信息。详细格式与边界见 [日志首版使用指南](日志首版使用指南.md)。

线上选样按 `created_at` 筛选请求窗口，`updated_at` 不是失败时间。动态分页和扫描预算截断不能保证取全。`observed_clusters` 是可重叠的候选签名组，不能与每任务唯一的主 `clusters` 混算或视为最终失败根因。

将 `HOLMES_GRAFANA_TOKEN` 留空表示尝试匿名查询；如果环境需要认证，配置只读 Token。已有接入验证中，独立匿名数据源查询返回 401，初次探测曾返回 403；浏览器登录态可以看日志，不表示后台匿名请求已经获授权。任务 API 可读取也不表示 Grafana 查询已获授权。

去掉 `--demo` 后启动实际服务：

```bash
java -jar target/holmes-java-0.1.0.jar web --port 8080
```

如果终端或 IDEA 的工作目录不确定，可明确指定配置文件：

```bash
java -jar target/holmes-java-0.1.0.jar web --env-file /path/to/holmes/.env --port 8080
```

只执行 `java -jar target/holmes-java-0.1.0.jar` 会显示帮助后退出，并不会启动网页。IDE 的 Program arguments 应填写 `web --env-file /path/to/holmes/.env --port 8080`，Working directory 设为项目根目录。`--env-file` 不改变工作目录；工具、手册、任务快照等相对路径仍从工作目录解析。若从其他目录启动，请在配置中为这些文件设置绝对路径。提示 `Address already in use` 时表示端口已被占用，可改用 `--port 8081`。

也可用 `--tasks`、`--log-file`、`--data-dir`、`--host`、`--port` 覆盖配置。默认只监听 `127.0.0.1:8080`。本地 HTTP 调试保持 `HOLMES_WEB_SECURE_COOKIE=false`；HTTPS 部署改为 `true`。

配置优先级为命令行参数 > 系统环境（含空值）> 所选 `.env` > 默认值。修改 `.env` 后重启进程；仅在启用可选密码时需要重新登录。IDE 运行配置中已有的同名环境变量会覆盖 `.env`。Docker Compose 仍通过 `env_file` 注入配置，不需要给容器里的 Java 额外传 `--env-file`。

## 通用问答和实际证据

需要真实问答时，沿用已有 `.env` 中的 `LLM_BASE_URL`、`LLM_MODEL` 和 `LLM_API_KEY`。没有可用模型配置时，日志调查仍可使用，页面会显示问答能力未启用。

生产默认工具配置为 [tools-web.json](../config/tools-web.json)，只允许读取 `data/evidence`，没有命令工具。该目录不会自动放入示例事故；需要调查文件时，由管理员将本次实际证据放入该目录。容器中的对应路径为 `/app/data/evidence`。修改工具配置或手册后重启服务；扩展规则见 [配置与扩展](配置与扩展.md)。

## 构建容器

仓库的 Dockerfile 使用预构建 JAR，不在镜像中安装 Maven 或重新编译。先用 JDK 27 打包，然后构建镜像：

```bash
mvn package
docker build -t holmes-java-web:local .
```

运行镜像固定为 `eclipse-temurin:27_35-jre-resolute`，该 Java 27 标签已在 [Docker Official Images 的 Temurin 清单](https://github.com/docker-library/official-images/blob/master/library/eclipse-temurin) 中核验；支持 Linux amd64 和 arm64。代理使用同样来自 [官方镜像清单](https://github.com/docker-library/official-images/blob/master/library/caddy) 的 `caddy:2.11.7-alpine`。升级版本时重新构建并验证。

`.dockerignore` 只允许 JAR、网页工具配置和手册进入构建上下文，`.env`、源码、本地日志、任务快照和数据目录均不进入镜像。应用以 UID/GID `10001:10001` 运行，根文件系统只读；工具配置和手册只读挂载。可写数据使用命名卷 `/app/data`，临时系统目录为有大小限制的 tmpfs。

## Compose 本地验证

默认不挂载任务文件，`HOLMES_LOG_TASKS_FILE` 留空即可走线上 API，不需要创建 `deploy/tasks` 目录。Compose 将数据目录固定为 `/app/data/holmes-log`，并清空 `HOLMES_LOG_FILE` 以使用 Grafana 日志来源。配置 `HOLMES_SCHEDULER_URL`、可选 Token 和来源时区后即可启动；其余分页与扫描预算默认值见 `.env.example`。

本地调试保持 `.env` 中网页密码留空、Secure Cookie 为 false，再启动：

```bash
docker compose --env-file .env config --quiet
docker compose --env-file .env up -d --build app
docker compose --env-file .env ps
docker compose --env-file .env logs --tail=50 app
```

默认仅发布宿主机 `127.0.0.1:8080`；浏览器访问本机地址。端口被占用时，在 `.env` 设置 `HOLMES_WEB_LOCAL_PORT=8081` 并重新创建容器。`config --quiet` 只验证配置，避免将解析后的密钥打印到终端。

Compose 将 `.env` 作为容器环境配置加载，不把文件复制进镜像。Compose 的 `.env` 解析会对未加引号或双引号中的 `$` 展开变量；含 `$` 的真实值使用单引号，随机网页密码建议使用上面的十六进制形式。[Docker 文档说明](https://docs.docker.com/reference/compose-file/services/#env_file)同时规定 `environment` 覆盖 `env_file`，所以仓库中固定的容器地址、路径与工具配置优先于本机值。

本项目未依赖 JRE 中可能不存在的 curl 来设置容器健康检查。容器处于 Running 只表示进程已启动；仍需在网页确认任务 API 选样、Grafana 查询和问答能力；配置密码后额外验证登录。日志批次创建先返回 202，在 `SELECTING_TASKS` 阶段异步读取任务 API，选定后固化名单，再采集日志。

离线回放或使用更完整的可信快照时，可额外创建 `compose.snapshot.yaml`，按实际路径只读挂载：

```yaml
services:
  app:
    environment:
      HOLMES_LOG_TASKS_FILE: /app/tasks/tasks.json
    volumes:
      - type: bind
        source: /实际路径/authoritative-tasks.json
        target: /app/tasks/tasks.json
        read_only: true
        bind:
          create_host_path: false
```

```bash
docker compose --env-file .env -f compose.yaml -f compose.snapshot.yaml up -d app
```

快照路径必须是容器内路径，运行用户 UID 10001 需要能读取该文件。移除该覆盖文件并将 `HOLMES_LOG_TASKS_FILE` 留空、重新创建容器，即恢复线上 API 来源。

## 远端 HTTPS

远端主机安装 Docker 与 Compose，准备已构建 JAR、Dockerfile、compose.yaml、config/tools-web.json、runbooks、deploy/Caddyfile，以及该主机自己的 `.env`。默认直接访问线上任务 API，无需任务文件。可在构建机器生成镜像后交付，也可在远端用同一 JAR 执行 `docker compose build`；远端运行不需要 Maven。

将域名 DNS 指向远端主机，允许外部访问 80/TCP、443/TCP；443/UDP 用于 HTTP/3，可按网络条件开放。在远端已有 `.env` 中配置实际域名与安全 Cookie：

```dotenv
HOLMES_DOMAIN=holmes.example.com
HOLMES_WEB_SECURE_COOKIE=true
HOLMES_WEB_PASSWORD=
```

`HOLMES_DOMAIN` 填裸域名，不加协议或路径。确认真实模型、任务 API、Grafana 权限和 FluxDrop 配置后启动 proxy profile：

```bash
docker compose --env-file .env --profile proxy config --quiet
docker compose --env-file .env --profile proxy up -d --build
docker compose --env-file .env --profile proxy logs --tail=50 proxy app
```

Caddy 对该域名自动申请和续期 HTTPS 证书，证书状态持久化到独立命名卷。proxy 在缺少域名或 `HOLMES_WEB_SECURE_COOKIE=true` 时会拒绝启动，不要求配置网页密码；应用 8080 仍只发布在宿主机回环地址，公网入口统一经 Caddy。浏览器使用 `https://实际域名` 直接进入页面。以后启用密码时也使用该 HTTPS 地址验证带 Secure 标记的登录会话。

页面、登录、日志批次和问答 API 共享同一域名，代理不改写路径或 Host。日志创建返回 202，页面按批次 ID 轮询；问答同步等待。代理等待响应的上限设为 45 分钟，覆盖默认 8 轮、每轮模型 90 秒和最多 3 次 HTTP 尝试及工具预算；若主动提高模型或调查预算，需要相应调整。[Caddy transport 配置](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#transports)说明了这些超时的作用。

修改远端配置后重新创建应用容器，再打开页面：

```bash
docker compose --env-file .env --profile proxy up -d --force-recreate app proxy
```

## 数据、容量和升级

应用数据卷保存轻量报告、检查点、临时分块和管理员证据；重建容器保留卷。报告和检查点默认 7 天有效、总量 100 MiB、单批 2 MiB；spool 上限 256 MiB、单块未压缩输入 16 MiB。每批默认读取最多 100000 条 / 64 MiB，运行预算 300 秒。Compose 显式保留这些约束，并限制应用内存 1 GiB 和容器日志轮转。

这些是应用对报告与 spool 的配额，不是 Docker 命名卷的文件系统硬配额；管理员额外放入的 evidence、证书及其他文件需要单独规划容量。自有崩溃遗留分块在服务重启时回收，外来文件、未知文件和符号链接保留并继续计入适用的容量限制。不要给同一数据目录启动多个应用副本。

`raw_archive=none` 不保存采集日志全集；显式 required 时，大日志脱敏后上传 FluxDrop，完成后清理本地分块。FluxDrop 远端的保留期、鉴权、容量配额和删除契约目前仍需服务端确认；存在下载引用不等于保证长期留存。恢复和状态边界见 [日志首版使用指南](日志首版使用指南.md)。

升级时重新打包、构建和启动应用即可：

```bash
mvn package
docker compose --env-file .env --profile proxy up -d --build app
```

本地未启用代理时去掉 `--profile proxy`。`docker compose down` 保留命名卷；只有明确要删除报告、证据和证书时才使用删除卷的命令。生产验收仍需任务 API 返回契约、Grafana 查询权限、FluxDrop 契约及真实模型请求的联合验证；尚不能宣称生产全链路已经跑通。

## 日志 LLM 解释

与通用问答共用服务端 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`，修改后须重启服务。新版首页只保留“发现高频错误”：服务器自动选择最近24小时、最多50个当前失败任务，配置模型时自动将本批脱敏结构化代表证据发送到页面标明的目的地。模型自主调用本批只读证据工具，再给解释建议；未配置时使用规则生成卡片。已有报告仍可点击“生成 LLM 解释”。没有可用关联证据会直接跳过。解释失败不会丢失规则结果，也不能补齐最终执行归属。详细请求、状态与数据流见[日志使用指南](日志首版使用指南.md#可选-llm-解释启动请求与结果)。
