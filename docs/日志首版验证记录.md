## 匿名读取复核

独立 HTTP 请求不带 Cookie 或 Authorization，结果如下：

| 入口 | 状态 | 诊断 |
| --- | ---: | --- |
| `/api/health` | 200 | 返回 Grafana 健康 JSON |
| `/api/user` | 401 | `Unauthorized` |
| `/api/dashboards/uid/single-pod-logs` | 401 | `Unauthorized` |
| `POST /api/ds/query?ds_type=victoriametrics-logs-datasource` | 401 | 与 Query Inspector 一致的查询结构；增加 `X-Grafana-Org-Id: 1`、同源 Origin/Referer 后仍为 401 |
| `/api/datasources/uid/victorialogs` | 401 | 数据源元数据同样拒绝匿名读取 |

现有 Chrome 页面的 Profile 菜单显示 `admin` 和 `Sign out`。该浏览器登录态与独立匿名 API 是不同的验证条件，网页可读不能替代匿名查询验证。普通组织与来源请求头未能解决 401，当前没有证据表明该错误来自适配器查询字段，仍需确认实际匿名入口或服务端访问策略。

## 线上任务自动读取验证（2026-10-15，Asia/Bangkok）

已按用户提供的任务统计网页接入只读 `GET /api/task-statistics/page`。实际响应包含 `data.tasks`、`page`、`page_size`、`total_count`、`timezone` 和 `fetched_at`；任务的 `task_id` 对应用户确认的日志 UUID。页面使用 `Asia/Hong_Kong` 日期范围，状态 `-1` 为读取时失败、`2` 为成功。

本地打包网页已通过浏览器创建真实批次：自动选定并处理 3 个失败任务，无需人工生成任务文件。批次最终为 `PARTIAL`，`selection_status=READY`；读取期间总数变化及跨页重复使 `selection_complete=false`，没有宣称全量或原子快照。随后真实 Grafana 查询返回 `GRAFANA_HTTP_401`，`retrieved_event_count=0`，因此尚未取得这些任务的真实日志或完成生产关联验收。本次未上传生产日志到 FluxDrop，也未调用模型解释。

调度器记录没有独立的 prompt / attempt / retry 清单。代码不把 `created_at`、`updated_at` 伪造成执行或失败时间；任务以 `TASK_ONLY` 关联，`failed_at` 保持未知。模拟日志联调验证了候选证据、`observed_signatures`、可重叠 `observed_clusters` 以及固定名单恢复；主簇保守保持 `INCOMPLETE`。

验证范围：完整回归 196 项加新增调度器适配器 12 项，共 208 项测试零失败；前端语法与英中展示烟测通过。Docker Compose 合成配置验证确认默认无需任务文件挂载；最终 JAR 已重新打包。真实任务读取成功不代表 Grafana 鉴权、最终重试归属或生产大日志归档已经验收。
